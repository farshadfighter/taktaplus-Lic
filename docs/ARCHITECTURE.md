# معماری سرور لایسنس TaktaPlus

> وضعیت: **پیش‌نویس برای تأیید** — تا تأیید نهایی، کدی نوشته نمی‌شود.
> سند معماری برنامه‌ی اصلی: [`taktaplus/docs/ARCHITECTURE.md`](https://github.com/farshadfighter/taktaplus/blob/main/docs/ARCHITECTURE.md)

## ۱. وظایف

1. صدور، تمدید، ابطال و جابه‌جایی لایسنس‌های TaktaPlus.
2. فعال‌سازی نصب‌ها به صورت آنلاین و آفلاین، و دریافت Heartbeat.
3. انتشار پکیج‌های سیگنیچر با Manifest امضاشده (مخزن مرکزی).
4. سه پنل: ادمین شرکت، پورتال مشتری، پورتال نماینده‌ی فروش.

## ۲. مدل لایسنس

| آیتم | واحد | ماژول‌های فعال |
|---|---|---|
| اشتراک دستگاه | یک سریال FortiGate یا FortiWeb، با تاریخ انقضا | مانیتورینگ، سیگنیچر، بکاپ/ریستور، گزارش، مدیریت متمرکز (اسکریپت، فرم‌ور، قالب و انطباق، Policy) |
| اشتراک 2FA | تعداد کاربر تعریف‌شده، با تاریخ انقضا | احراز هویت دو مرحله‌ای پیامکی |

- اعضای HA هر کدام یک اشتراک دستگاه جدا.
- هر آیتم انقضای مستقل دارد؛ یک لایسنس می‌تواند چند آیتم با تاریخ‌های مختلف داشته باشد.
- پس از انقضا: دوره‌ی مهلت (پیش‌فرض ۱۴ روز، قابل تنظیم برای هر مشتری)، سپس فقط‌خواندنی.
- **RMA:** جایگزینی سریال یک آیتم با سریال جدید، با حفظ تاریخ انقضا و ثبت در تاریخچه.

## ۳. فناوری

همسان با برنامه‌ی اصلی: Go (chi، pgx، sqlc، goose)، PostgreSQL، React + TypeScript + Ant Design (RTL)، استقرار با Docker Compose. این سرور **روی اینترنت** و در زیرساخت شرکت اجرا می‌شود.

## ۴. ساختار ریپازیتوری

```
taktaplus-lic/
├── cmd/
│   ├── licserver/            # API + پنل‌ها
│   └── lictool/              # CLI: ساخت کلید، امضای آفلاین، بررسی فایل
├── pkg/
│   ├── keys/                 # فرمت متنی کلید عمومی و Keyring (بر اساس kid)
│   ├── licformat/            # فرمت لایسنس، درخواست فعال‌سازی، بررسی امضا (برنامه‌ی اصلی import می‌کند)
│   └── manifest/             # فرمت Manifest پکیج و بررسی امضا (برنامه‌ی اصلی import می‌کند)
├── internal/
│   ├── api/                  # API عمومی (فعال‌سازی، Heartbeat، پکیج)
│   ├── admin/  customer/  reseller/   # API پنل‌ها
│   ├── auth/  audit/
│   ├── licensing/            # منطق صدور، تمدید، ابطال، RMA
│   ├── signer/               # دسترسی به کلید خصوصی (فایل رمزگذاری‌شده / HSM در آینده)
│   ├── packages/             # آپلود، امضای Manifest، سرو فایل
│   ├── billing/              # اعتبار و موجودی نمایندگان
│   └── store/
├── migrations/
├── web/
├── deploy/
└── docs/
```

`pkg/` فقط شامل **فرمت، امضا و بررسی امضا** است و هیچ کلید خصوصی‌ای در آن نیست. امضای درخواست با کلید نصب در خود برنامه‌ی اصلی انجام می‌شود؛ کلیدهای خصوصی مرجع لایسنس فقط در `internal/signer` (فایل رمزگذاری‌شده با scrypt + AES-256-GCM) بارگذاری می‌شوند.

## ۵. فرمت فایل لایسنس (`.tplic`)

```
TPLIC1.<base64url(payload_json)>.<base64url(ed25519_signature)>
```

```json
{
  "format": 1,
  "kid": "lic-2026-01",
  "license_id": "LIC-000123",
  "customer": { "id": "C-0042", "name": "…" },
  "installation_id": "…",
  "installation_pubkey": "…",
  "issued_at": "2026-10-25T10:00:00Z",
  "not_after": "2027-11-30T00:00:00Z",
  "grace_days": 14,
  "online": { "heartbeat_url": "https://lic.example.com/api/v1/heartbeat", "interval_hours": 24 },
  "devices": [
    { "serial": "FGT60FTK2209XXXX", "platform": "fortigate", "expires": "2027-10-25" },
    { "serial": "FV-1KF3R21000XXX", "platform": "fortiweb",  "expires": "2027-06-01" }
  ],
  "otp": [
    { "users": 100, "expires": "2027-10-25" }
  ]
}
```

- امضا روی `TPLIC1 || 0x00 || payload_json` (پیشوند هر نوع سند، دامنه‌ی امضا هم هست تا امضای یک نوع سند برای نوع دیگر قابل استفاده نباشد). کلید با `kid` مشخص می‌شود تا چرخش کلید ممکن باشد؛ برنامه‌ی اصلی فهرست کلیدهای عمومی معتبر را دارد.
- `not_after` = دیرترین انقضا + مهلت؛ پس از آن کل فایل نامعتبر است.
- لایسنس به `installation_pubkey` گره خورده است؛ کپی فایل روی نصب دیگر کار نمی‌کند.
- `installation_id` از هش کلید عمومی نصب ساخته می‌شود (۲۴ کاراکتر base32 در گروه‌های ۴تایی). اثرانگشت سخت‌افزار جدا در درخواست ارسال و با تحمل تغییر یک جزء بررسی می‌شود.
- هر آیتم تا پایان روز `expires` (UTC) فعال است، سپس `grace_days` روز در مهلت، و بعد منقضی.

## ۶. فعال‌سازی

### آنلاین

```
TaktaPlus ──POST /api/v1/activate {license_key, installation_id, pubkey, fingerprint, version} + امضای کلید نصب──▶ licserver
          ◀── .tplic ──
TaktaPlus ──POST /api/v1/heartbeat {license_id, installation_id, usage{devices, otp_users}, version} (امضاشده)──▶
          ◀── .tplic جدید یا وضعیت ابطال ──
```

- `license_key`: کد فعال‌سازی که هنگام فروش به مشتری داده می‌شود (مثلاً `TPK-XXXX-XXXX-XXXX-XXXX`).
- یک لایسنس در هر لحظه فقط به یک نصب متصل است. انتقال به سرور جدید از پورتال مشتری/ادمین (آزادسازی نصب قبلی) انجام می‌شود.
- اگر Heartbeat برای مدت طولانی نرسد، لایسنس همچنان تا `not_after` معتبر است (حالت آفلاین مجاز).

### آفلاین

```
TaktaPlus پنل ──دانلود──▶ request.tpreq (امضاشده با کلید نصب)
مشتری/نماینده ──آپلود در پورتال──▶ licserver ──▶ license.tplic ──آپلود در پنل TaktaPlus──▶ فعال
```

همین مسیر برای تمدید و افزودن سریال در حالت آفلاین استفاده می‌شود.

## ۷. مخزن مرکزی پکیج‌ها

- ادمین شرکت پکیج‌ها (دریافت‌شده از پورتال فورتی‌نت) را آپلود می‌کند و نوع، نسخه، مدل‌ها و بازه‌ی فرم‌ور را مشخص می‌کند.
- Imageهای فرم‌ور هم در همین مخزن با نوع `firmware` منتشر می‌شوند و فیلد `upgrade_from` نسخه‌هایی را که مستقیم به این Image ارتقا پیدا می‌کنند مشخص می‌کند (ماژول F2 برنامه‌ی اصلی).
- سرور `manifest.json` را می‌سازد و با **کلید انتشار پکیج** (جدا از کلید لایسنس) امضا می‌کند. فرمت در سند برنامه‌ی اصلی، بخش ۹.۲.
- API نصب‌ها:
  - `GET /api/v1/repo/manifest` و `GET /api/v1/repo/manifest.sig`
  - `GET /api/v1/repo/files/{sha256}` (فقط فایل‌های Manifest فعلی)
  - احراز هویت: هدر `Authorization: TPAUTH1 <license_id>.<installation_id>.<unix>.<sig>` که با کلید نصب روی متد، مسیر و زمان (حداکثر ۵ دقیقه اختلاف) امضا می‌شود (`pkg/repoauth`). فقط لایسنس فعالِ متصل به همان نصب که دست‌کم یک اشتراک دستگاه فعال یا در مهلت دارد.
- چرخه‌ی پکیج: بارگذاری (پیش‌نویس) ← «انتشار» ← امضای Manifest جدید. بازپس‌گیری با انتشار بعدی از Manifest حذف می‌شود.
- خروجی بسته‌ی آفلاین (`zip` شامل Manifest امضاشده + فایل‌ها) برای مشتریان بدون اینترنت، از پورتال مشتری/نماینده.
- نگهداری فایل‌ها روی دیسک یا S3/MinIO.

## ۸. پنل‌ها

### ادمین شرکت
- مشتریان، نمایندگان، کاربران و نقش‌ها.
- محصولات و تعرفه‌ها (اشتراک دستگاه FortiGate/FortiWeb، بسته‌های کاربر 2FA، مدت).
- صدور لایسنس، افزودن/حذف سریال، تمدید، RMA، ابطال، آزادسازی نصب.
- مشاهده‌ی نصب‌ها، آخرین Heartbeat، نسخه‌ی نرم‌افزار و مصرف.
- مدیریت مخزن پکیج‌ها.
- تخصیص اعتبار/موجودی به نمایندگان.
- گزارش فروش، انقضاهای پیش رو، لاگ ممیزی.

### پورتال مشتری
- مشاهده‌ی لایسنس‌ها، سریال‌ها و تاریخ انقضا.
- فعال‌سازی آفلاین (آپلود `.tpreq`، دانلود `.tplic`).
- درخواست تمدید، جابه‌جایی سرور، RMA.
- دانلود بسته‌ی آفلاین پکیج‌ها و نسخه‌های نرم‌افزار.

### پورتال نماینده‌ی فروش
- مدیریت مشتریان خود.
- صدور و تمدید لایسنس از محل موجودی/اعتبار تخصیصی.
- همه‌ی قابلیت‌های پورتال مشتری برای مشتریان خود.
- گزارش فروش و انقضاهای پیش رو.

## ۹. مدل داده (جداول اصلی)

| جدول | محتوا |
|---|---|
| `organizations` | شرکت، نماینده، مشتری (با `parent_id` برای مشتریان نماینده) |
| `users`, `roles`, `sessions` | کاربران پنل‌ها |
| `products` | انواع اشتراک و تعرفه |
| `orders`, `order_items` | سفارش‌ها |
| `licenses` | لایسنس، مشتری، کد فعال‌سازی، وضعیت، مهلت |
| `license_items` | آیتم‌ها: سریال/پلتفرم یا تعداد کاربر، شروع، انقضا |
| `serial_history` | تاریخچه‌ی RMA و جابه‌جایی سریال |
| `installations` | شناسه‌ی نصب، کلید عمومی، اثرانگشت، وضعیت |
| `activations`, `heartbeats` | رویدادهای فعال‌سازی و Heartbeat |
| `issued_files` | هر فایل `.tplic` صادرشده (hash، زمان، صادرکننده) |
| `reseller_credits`, `credit_transactions` | اعتبار نمایندگان |
| `packages`, `manifests` | مخزن پکیج |
| `signing_keys` | متادیتای کلیدها (`kid`، نوع، وضعیت) — **بدون کلید خصوصی** |
| `audit_log` | ممیزی |

## ۱۰. امنیت

- **کلیدهای خصوصی** (لایسنس و انتشار پکیج) هرگز در ریپازیتوری یا دیتابیس نیستند: فایل رمزگذاری‌شده روی سرور که مسیر و رمز آن از متغیر محیطی/Secret خوانده می‌شود. در آینده: HSM یا امضای آفلاین با `lictool`.
- ریپازیتوری Public است؛ امنیت فقط به امضای رمزنگاری متکی است.
- همه‌ی درخواست‌های فعال‌سازی و Heartbeat با کلید نصب امضا می‌شوند؛ Rate limit و قفل موقت روی کد فعال‌سازی.
- 2FA برای کاربران همه‌ی پنل‌ها.
- لاگ ممیزی برای هر صدور، تغییر و ابطال.
